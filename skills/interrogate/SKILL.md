# Interrogate

Question the user in rounds until nothing important is open or silently assumed.

| Mode | Use when | Ends with |
|---|---|---|
| **Decide** | A plan, design or choice has open branches | Every branch decided |
| **Articulate** | The user roughly knows what they mean but not how to say it (email, argument, thesis claim, prompt) | A confirmed **core statement** |

## Steps

1. **Pick the mode** and name it in the first round; ask first if unclear. Start when the user asks; for a vague, costly request offer it in one line and start on a yes.
2. **Map the tree.** Decide: the decisions and their dependencies. Articulate: intent, audience, key point, desired reader reaction, constraints (tone, length, channel).
3. **Look up facts yourself** (files, docs, web, memory). Put only judgments and preferences to the user.
4. **Ask the frontier**: questions whose prerequisites are answered, at most 4 per round, those that unblock the most first. Questions that depend on an open one wait.
5. **Update the tree** after each answer, recompute the frontier, repeat.
6. **Finish** when the frontier is empty: give the summary below and act once the user confirms.

## Question format

- Use the multiple-choice question UI for enumerable answers, numbered text for open ones; mix within a round when needed.
- One concept per question, short, neutral.
- Decide: put a recommended answer first, phrased so "yes" accepts it.
- Articulate: offer contrasting options or reflect the user's own words ("You said X twice: is that the point?"); a recommendation plants your framing.
- Answer "it depends" or abstract: ask for the concrete case.

## Summary

- Decide: decisions (one line each), parked items, open risks.
- Articulate: the core statement in one sentence, plus audience, intended effect, constraints.

After confirmation, hand off to design-capture or the actual task.
