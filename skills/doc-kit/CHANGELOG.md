# Changelog

All notable changes to doc-kit. Versions follow [SemVer](https://semver.org/).

## 0.5.0 — System map page
The interactive system map is generated by the lint, so showing the state of a design costs the agent no writing.

- **Added**
  - `kit/tools/doclint.py` — `--system-map [OUT.html]`: writes the system map page from front matter and the dependency graph.
    - `system_map_data`: nodes (code, title, layer, status, open questions, purpose line, folder as group), edges, and a bottom line with cycles and fan-out breaches.
    - `write_system_map`: fills `doclint_assets/system-map.html`; exit code 2 without `coupling` or without the template.
    - `system_map` config key: `{out, title}`.
  - `kit/tools/doclint_assets/system-map.html` — the page template, moved here from the handoff skill.
  - `examples/tidewatch/` — a small invented design project that lints clean under the unchanged design preset.
  - `tests/test_example.py` — the example stays clean, its committed map is current, its page builds.
  - `tests/test_doclint.py` — `Coupling`: page data from front matter, custom path and fan-out flag, exit code without `coupling`.
- **Changed**
  - `CONFIG.md`, `kit/templates/design/docs/CONVENTIONS.md` — the fan-out limit is per project: override `coupling.max_fan_out` in the project's config and give the reason in its conventions.
  - `kit/templates/*/docs/CONVENTIONS.md` — the `playbook` row of *Skills in use* applies where that skill is installed.
  - `SKILL.md`, `CONFIG.md`, design templates — document `--system-map`.
- **Removed**
  - `README.md` — its test commands live in the repository README; a skill folder carries no README.
  - `examples/wayfarer/`, `tests/regression_wayfarer.py` — moved out of the skill to `evals/regression/wayfarer/`.

## 0.4.0 — Coupling
Specs depend on interfaces, not on each other's rules; the lint makes coupling visible.

- **Added**
  - `kit/tools/doclint.py` — `coupling`: config-driven checks, all off when the key is absent.
    - `scan_coupling`, `check_coupling`: warning for a rule or parameter line citing a rule ID of another system (message names the fix); interface item IDs `<CODE>-I<n>` (duplicate or foreign code is an error, as for rules); warning for fan-out above `max_fan_out`.
    - `find_cycles`, `check_cycles`: one warning per dependency cycle with its path (no cycle check existed before).
    - `check_refs`: a cited interface item that the target spec does not define is a warning.
    - `coupling_report`, `--coupling`: per-system fan-out, fan-in, foreign rule references, interface items, and the cycles; plain text, sorted by code.
  - `kit/templates/design/docs/templates/spec.md` — *Interface* section between *Intent* and *Rules*.
  - `tests/test_doclint.py` — `Coupling`: each check fires and is exempt where documented, 2-cycle and 3-cycle, dense-graph cycle search, `--coupling` output, off without the key, template shape, Wayfarer example config untouched.
- **Changed**
  - `kit/presets/design.json` — enables `coupling` for `spec` with `max_fan_out` 5.
  - `kit/templates/design/docs/CONVENTIONS.md` — *Interface* paragraph in section 6, interface item row in the ID table (+61 words).
  - `kit/tools/doclint.py` — version 0.4.0; `id_scheme.interface` (default `I`) is read only when `coupling` is configured.
  - `CONFIG.md`, `SKILL.md` — document `coupling` and `--coupling`.
  - `tools/doclint.py` — synced with the kit copy.

## 0.3.0 — Probe, ascend and early-quantity lint
Layers gain probe and ascend, and human-side failures (early numbers, oversized questions, late-found conflicts, overlong histories) get mechanisms instead of instructions.

- **Added**
  - `kit/tools/doclint.py` — `early_quantity`: config-driven check (warning) for a quantity in a rule line of a document below a configured layer; `QUANTITY` is the default pattern. Off when not configured.
  - `kit/presets/design.json` — enables `early_quantity` for `spec` below `L3`.
  - `kit/templates/*/docs/CONVENTIONS.md` — *Skills in use* table and the instruction-writing rule.
  - `kit/templates/design/docs/CONVENTIONS.md` — moves (park, probe, ascend), orderings and tiers, question size, pivotal-decisions-only rule.
  - `kit/templates/design/docs/planning/OPEN_QUESTIONS.md` — *Needs build* section.
  - `tests/test_doclint.py` — `EarlyQuantity` (fires, tag/layer/line/inline-code/config exemptions, configurable) and `VocabularyTags` (new tags and status lint clean).
- **Changed**
  - `kit/presets/design.json` — rule tag `conflicting`, question tag `needs-build`, system status `validated`.
  - `kit/templates/design/docs/CONVENTIONS.md` — vocabulary for the new tags and status; `placeholder` means a number that must be kept; lint-enforced rules shortened to `(lint)` pointers and rules phrased positively; the front matter example and the decision entry example point to the templates; decision entries are for pivotal decisions.
  - `kit/templates/basic/docs/CONVENTIONS.md` — lint-enforced writing rules shortened to `(lint)` pointers.
  - `kit/templates/design/docs/templates/decisions.md` — pivotal-decisions line; optional `supersedes` field.
  - `kit/tools/doclint.py` — version 0.3.0.
  - `CONFIG.md`, `SKILL.md` — document `early_quantity`.

## 0.2.1 — Fewer false positives, filtered index
Found while linting the first playbook library: quoting a word as an example tripped the first-person check, and the index listed run logs next to playbooks.

- **Fixed**
  - `kit/tools/doclint.py` — `check_body`: first-person check ignores inline code spans.
- **Added**
  - `kit/tools/doclint.py` — `build_map`: `map.types` limits a files-sourced index to the listed doc types.
  - `tests/test_doclint.py` — tests for both.

## 0.2.0 — Playbooks and run logs as doc types
Supports the `playbook` skill: workflows worked out by trial and error get a checked home next to the other docs.

- **Added**
  - `kit/templates/*/docs/templates/playbook.md`, `run-log.md` — playbook (steps with done-conditions, gotchas, verify) and its run log (dated attempts table).
  - Presets: types `playbook` (requires `runs`; prose rules apply; ~1,200-word budget) and `runlog` (exempt from prose rules); `last_run` date field.
  - `tests/test_doclint.py` — `Playbooks`: templates lint clean in both presets, per-type statuses, required fields, first person allowed in run logs.
- **Changed**
  - `kit/tools/doclint.py` — `check_front_matter`: `types.<type>.enums` override the global enums, so a design project's playbooks use `draft · current · deprecated` while specs keep their lifecycle.
  - Templates: CONVENTIONS doc-type tables and PROJECT_STRUCTURE list `playbooks/`.
  - `CONFIG.md`, `SKILL.md` — document the above.

## 0.1.0 — Initial kit, generalized from Wayfarer's doclint
Wayfarer's lint proved that mechanical doc rules work best as a deterministic check; this release makes it reusable across projects via config.

- **Added**
  - `kit/tools/doclint.py` — config-driven lint core (stdlib only, Python 3.7+).
    - `Project` / `Doc` — discovery, front matter parsing, section-aware line walk.
    - Checks: links, stale terms + glossary retired names, front matter (types, required keys, enums, dates, code table, id-path match, unique ids), decision logs, mirror files, rule/question IDs and tags (incl. section-only tags), cross-file ID references, index listing, prose rules, custom regex patterns, word budget.
    - `build_map` — generated index from the code table (`source: codes`) or from every file's front matter (`source: files`).
    - Plugin hooks: `check_any`, `check_migrated`, `check_project`, `summary`, `verbose`.
  - `kit/tools/doclint_plugins/style.py` — optional warnings: long sentences, bold density (IDs excluded), emoji in prose.
  - `kit/presets/basic.json`, `kit/presets/design.json` — starting configs.
  - `kit/templates/basic/`, `kit/templates/design/` — entry files (README, PROJECT_STRUCTURE, CONVENTIONS, GLOSSARY, map) and, for design, spec/decisions/data templates, vision, parking lot, open-questions index.
  - `kit/tools/hooks/pre-commit` — errors block commits, warnings don't.
  - `examples/wayfarer/` — Wayfarer config + plugin (migration inbox, provisional-rule citations, legacy open-question entries).
  - `tests/test_doclint.py` — 27 unit tests incl. clean-scaffold checks for both template sets.
  - `tests/regression_wayfarer.py` — fault-injection comparison against Wayfarer's original lint.
  - `CONFIG.md` — configuration reference.
- **Changed** (vs. Wayfarer's original lint)
  - First-person check also catches sentence-initial "My".
  - Three messages reworded to be project-neutral (code table, changelog heading, provisional tag).
  - Design preset: release-scheduling pattern also catches "v2." at a sentence end; Wayfarer's example config keeps the original pattern.
- **Fixed**
  - Unknown front-matter `type` reported as an error; the original lint crashed with a `TypeError`.
